# 上架物料：meta 段 + STOREFRONT.md

商品页上显示的每一样东西都由**卡自己声明**——平台不靠上传表单去补（表单能盖掉包内声明的话，
页面讲一套、包里另一套，买家解包才发现）。

## meta 段物料

| 物料 | 声明在 | 收什么 |
|---|---|---|
| 一句话简介 | `meta.description` | 文本 |
| 封面 | `meta.cover` | http(s) 外链 或 卡内相对路径 |
| 预告片 | `meta.trailer` | **仅 http(s) 外链**（视频打进卡包会让分发体积失控） |
| 截图廊 | `meta.preview[]` | 外链或卡内路径，最多 6 张 |
| 市场介绍长文 | `STOREFRONT.md` | Markdown |

解析规则：外链原样用（平台不托管不代理）；卡内相对路径由平台从包里取出托管（作者没有 CDN
也能发）。路径一律遏制在卡根内，`..` 与绝对路径不认。

## STOREFRONT.md 规范

每张要上架的卡都该带一份市场介绍长文。它与卡里其它文档**职责不同、不许合并**：

| 文件 | 读者 | 回答什么 |
|---|---|---|
| `STOREFRONT.md` | **还没买的人** | 这套做法是什么、做出来长什么样、适合谁、带走的是什么 |
| `README.md` | 拿到卡之后的人 | 目录怎么用、要装什么、怎么跑起来 |
| 创作宪章 / 风格锁文档 | 执行时的人与 AI | 频道口径与不可越线的约束 |

写作规则：

- 位置：卡根 `STOREFRONT.md`（也认 `市场介绍.md`）；想放别处写 `meta.storefront: "<相对路径>"`。
- 上限 256KB；渲染时 sanitize（禁 raw html）。
- **不要用卡名做一级标题开头**——商品页已把名字印在头上，从第一段正文写起，小节用 `##`。
- 缺这份文件不拒发布，但商品页会退回只显示一句 `description`；**绝不拿 README 顶替**——
  那是拿开发者文档去卖货，读者对不上。

## 打包瘦身（bundle.omit）

分发能不能成立取决于包的体积。挑「买家真正需要的」：授权允许的字体、logo、色板、
提示词、复用片段进包；重媒体（大素材库、IP 专属帧序列、历史成片）声明进 `bundle.omit`
并写清 `reason`——一条声明同时服务两处：打包时跳过、导入披露屏告诉对方「这块要你自己补」。

随卡示例内容（让买家不建内容就能看出产出长什么样）声明 `bundle.demo`：
`{ path, license: "sample-only"(默认) | "cc-by" | "inherit", reel? }`。示例住卡内独立目录，
不进 contentDir（示例不是频道内容，混进去会污染条目列表与体检判据）。
