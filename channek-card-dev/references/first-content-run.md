# 首条内容实战：写完卡之后的那一半

**卡合法 ≠ 卡能用。** 这份记的是：卡写完了，第一次拿它真跑一条内容时会踩什么。

**读者是卡的开发者**，不是收卡人——收卡人拿到的卡里已经带着 `skills/`（见 SKILL.md
「卡要带频道 skill」那节），那份才是给他们的。你现在要做的是**把这张卡跑通一次**，
顺便把跑通过程中攒下的经验写进卡自己的 skills 里。

> **为什么单独列一份**：一张合法的卡 + 一堆装好的插件，不等于会做内容。
> 2026-08-26 首次在飞轮日记之外开新频道（比奇堡经济学），一天里踩的坑没有一个是「卡写错了」，
> 全部是「不知道 Channek 的活该怎么干」——自己写 ffmpeg 干了渲染能力的活、把取值写死在脚本里、
> 素材放错层、用测不到那个错误的指标验收。**那些经验在老频道的卡里，新频道看不见。**
> 这一册就是把它搬出来。

## 三条铁律（先背这个，其余都是它的展开）

| | 铁律 | 违反的样子 |
|---|---|---|
| ① | **活让能力干**：`channek invoke <能力id>` | 自己写 ffmpeg / python 脚本合成、渲染、混音 |
| ② | **取值读卡**：`channek card <点号路径>` | 把配速、尺寸、字幕行宽、画风提示词写死在脚本里 |
| ③ | **工件说语义 id**：`channek.master`，不说 `master.mp4` | 写死文件名——换一张卡当场瞎 |

四条命令就是全部接口：

```bash
channek card <点号路径>       # 取值。整段用 channek card layout.artifacts
channek caps                  # 有哪些能力、谁提供、缺的给人话提示
channek cap <能力id>          # 这条能力吃什么参数（★ 调之前先问它，别背参数表）
channek invoke <能力id> 参数=值 --out <目录>
```

**能力缺了怎么办**：停在这一步，如实记账（缺哪条、装什么能续）。
**不许用别的手段顶替**——不写脚本自己干、不找外部工具、不拿生成内容冒充。
不依赖这条产物的后续步可以继续，依赖的一律不往下走。

> 实测教训：Remotion 没装 → `channek.render-master` 不可用。正确动作是停下记账；
> 实际做的是写了个 ffmpeg 粗剪脚本顶上，还渲了七八版——**每一版都在给一条注定要重做的路加码**。

## 一条内容怎么跑

**先读卡，别猜**：`channek card pipeline.steps`（有哪些步、什么顺序）、
`channek card layout.artifacts`（每步产物落哪，键 = 语义 id）。步序**以卡为准**，
九步是常见形态不是常量。

### 交接链：每步只对下一步负责一件事

| 步 | 吃什么 | **交出什么**（这一列是命门） |
|---|---|---|
| 选题 | 一句意图 | 条目清单；一条视频只回答一个问题 |
| 脚本 | 选题 | 口播稿；**字数上限 = 卡的配速 × 秒数** |
| 分镜 | 口播稿 | 画面清单；**时间留空**——镜长必须等配音出来后派生 |
| 素材 | 各镜素材需求 | 素材落库 + 镜里的槽位被填上 |
| 配音 | 各镜旁白 + 频道音色 | 旁白轨；**每镜镜长按真实音频定死** |
| 字幕 | 旁白轨 + **口播稿原文** | 字幕轨（文本真相来自原稿，不是识别结果） |
| 剪辑 | 定死镜长的分镜 + 字幕 + 素材 | 成片母版 |
| 封面 | 成片 | 封面（横竖分别生成） |
| 发布 | 成片 + 封面 | 分发物（一平台一份） |

### 三处顺序不能换

1. **配音在剪辑之前**——镜长按真实音频定死再渲。反过来要全片重渲，中间必然出现「画面演完了、静等念稿」的死冻。
2. **字幕在剪辑之前**——对旁白轨对齐产 cue，剪辑一遍烤进去。成片出来再叠 = 又一次全片重渲。
3. **素材在剪辑之前**——缺素材的镜别指望渲染时补。

### 进度 = 工件在不在

**不写状态文件、不维护状态机。** 语义 id 对应的工件在，这步就是做完的。
app 的灯轨也这么读，两边同源；断点续跑天然成立——扫一遍工件，缺哪步做哪步。

## 一张卡该带哪些 skill

**频道的方法论属于卡**，跟着卡走、随卡分发。收卡人拿到的不只是配置，还有「这个频道怎么做内容」。

```
风格卡/skills/
├── _shared/读卡与调能力.md   ← 上面三条铁律的展开 + 本频道的取值速查表
├── <每一步>-craft/           ← 一步一份：吃什么、交出什么、读哪些卡值、调哪条能力、自检、卡住怎么办
└── produce-flow/             ← 总编排：交接链、顺序约束、卡住退回哪
```

在卡的 `layout.cardAssets.libraries.skills` 声明它，并软链到频道根 `.claude/skills/`。

**每份 SKILL.md 的骨架**：frontmatter（何时用/不用）→ 吃什么/交出什么（**语义 id**）→
怎么做（引用卡的 `prompts/`，别复制判据）→ 要读的卡值（说明为什么不能写死）→
要调的能力（**只写 id**）→ 交出前自检 → 卡住怎么办。

> `prompts/` 与 `skills/` 的分工：prompts 是**喂给模型的作业指令**（卡的 `prompts` 段引用它），
> skill 是**给 agent 的操作手册**。skill 引用 prompts，不复制——复制就是第二个真相源。

## 素材分层：公共的进卡，专属的进条目

| 放什么 | 落哪 |
|---|---|
| **公共参考**：角色定妆图、跨条目复用的资产 | 卡内素材库 |
| **这一条片的**动作、表情、场景、道具 | 条目下的生成图落点（语义 id） |
| 抠好的透明件 | 条目下的精灵落点（语义 id） |

判据：**换一条片还用得上的 → 卡级；只在这条片里成立的 → 条目下。**

检索顺序**条目优先、卡级兜底**——顺序反了，这条片会悄悄用上别条片的图。

> 实测教训：把 35 张全塞进卡级素材库，条目下声明的落点全是空目录，
> app 灯轨直接显示「素材步没产物」。**卡声明了落点却不往里放，等于这一步没做。**

## 验收：指标要能测到那个错误

**做过的每一次改进，验收指标必须能测到你想防的那个错误。** 否则指标全绿而东西是坏的——
那比指标飘更危险，因为它让人停止怀疑。

| 实测 | 量了什么 | 结果 | 真相 |
|---|---|---|---|
| TTS 换了个模式 | 声纹相似度 ↑ · 响度摆动 ↓ · 语速摆动 ↓ | 三项全优 | 模型把参考音那段话也念了进去，8 个字念 22 秒。**形态指标测不到念错字** |
| 判断音色飘不飘 | 频谱质心 · 自相关 F0 | 「飘得厉害」 | 那两个指标对**文本内容**极敏感，测不出说话人身份。换专门的声纹度量一测：**从来没飘过** |
| 检查角色图 | 缩略图扫一遍 | 「都正常」 | 有一张长了四只眼。**把头部裁出来拼一张，一次全暴露** |

**规矩**：改了**内容生成**（TTS / 出图 / 文案）→ 验收必须含**内容正确性**（转写比对、逐张看图），
不能只看相似度、响度这类形态指标。判断「是不是同一个人 / 同一个角色」→ 用**专门的度量**，
别用频谱、直方图这些代理。看不清就**放大了看**。

## 水土不服清单

新频道最容易踩的，按代价排：

| 症状 | 根因 | 正解 |
|---|---|---|
| 自己写脚本干活，越写越多 | 没意识到能力是唯一入口 | 铁律① |
| 换个频道 / 换台机器就跑不动 | 取值和路径写死在脚本里 | 铁律②③ |
| 改了个「优化」，指标全绿但产物是坏的 | 验收指标测不到那个错误 | 见上一节 |
| 素材放了但 app 说没做 | 放在卡级，没放进卡声明的条目落点 | 见素材分层 |
| 音画对不上，越长偏得越多 | 用秒对齐片段 | **用帧数**——秒对齐在几十个片段上会累积出十几秒 |
| 改了本机某个 skill，别人机器上没有 | 改错了落点 | 能力实现随插件分发；本机 skill 只是**源**，插件自带副本才是收卡人跑的那份 |
| 卡合法却处处不对劲 | 卡没带 skills/，方法论只在作者脑子里 | 见「一张卡该带哪些 skill」 |

## 硬禁止

- ❌ 绕过 `channek invoke` 自己写脚本干活
- ❌ 写死取值（配速 / 尺寸 / 行宽 / 阈值 / 提示词）——读卡
- ❌ 写死工件文件名——说语义 id
- ❌ 背能力参数表——`channek cap <id>` 问它
- ❌ 引用本机绝对路径——收卡人机器上没有
- ❌ 写状态机——进度就是工件在不在
- ❌ 用测不到该错误的指标验收
- ❌ 能力缺了用别的手段顶替
