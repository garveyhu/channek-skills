# 07 · 风格资产与发布配置：频道的脸与法

> 这一层回答「复刻这个频道，复刻的到底是什么」。答案是：**判据文档 + design token + 发布口径**
> ——不是那些图片。

## 三套指引机制，以及「没有第四套」

卡的 README 开篇立的这张表是整层的宪法：

| 机制 | 谁在读 | 长什么样 |
|---|---|---|
| ① **卡里的声明** | 宿主与插件 | `layout.cardAssets.*` 声明目录、`layout.artifacts` 声明落点、`brand.*` 给内联值。**声明的是位置与取值，不是行为** |
| ② **语义 id + 能力** | skill 里的命令 | 产物用语义 id 说，路径经 `channek card` 解析；干活一律 `channek invoke` |
| ③ **md 指引 agent** | 写东西的 AI | 创意步靠 `skills/` 与 `风格锁/` 约束，不靠机器判 |

> **没有第四套。** 出现「某个脚本按固定名去扫某个目录」这种硬约定，就是在卡之外又建了一份
> 真相源——换一张目录结构不同的卡时它会**静默失灵**。

配一句定死值归属的话：

> **颜色、字体、配速、行宽、质量阈这些值不在任何文件夹里**——它们是 `card.json` 的内联值
> （`brand.tokens` / `config.*`），组件与 skill 一律去取，**不复制成第二份**。

## 创作宪章：立场归它，参数归 config

**32 行，是整层里唯一被称为「最高法律」的文件。** 它的开头两行就把分工钉死：

> 本文件是本频道的创作宪章（最高法律）。
> **机器值的单一事实源是 `card.json`（`identity` / `brand` / `voice`）；
> 人读「为什么」另见 `品牌套件/品牌文档/IP定位书.md`。**

| | 创作宪章.md | card.json 的 `config` 段 |
|---|---|---|
| 管什么 | **为什么这么做**——赛道、受众、价值主张、人设、招牌立场、视觉脸的**取向** | **具体取什么值**——8 组 54 个字段 |
| 谁读 | 写东西的人和 AI（机制 ③） | 宿主 + 各步 skill（机制 ①） |
| 谁能改 | 人改（改它 = 战略级变更） | **只能在 app 的卡设置里改** |
| 例子 | 「signature = <一句可辨识的视觉签名>」 | `channek.visual.seed=9`、`channek.voice.pace=5.13` |

**宪章不含任何数值；config 不含任何理由。** 冲突时以宪章为准，但**数值只从卡取，
宪章里绝不抄第二份**。

宪章里的每一条人设都带指针、不带值：

> **声音**：固定音色 `<档名>`（机器值 `card.json.voice.default`）+ 固定语速 / 停顿节奏
> （事实源 `品牌套件/音色/voice.md`）。

`config` 里的 `channek.freeze.*` 三个开关就是宪章的**机器执行面**——
宪章说「这张脸定了」，freeze 段让生成链**改不动**。

修订记录直接写触发条件：「改赛道 / 受众 / 人设 / 视觉脸 / 招牌立场就改这里 + `card.json` + `品牌套件/`。」

## 静态脸 / 动态脸：为什么分成两份锁

```
风格锁/
├── 画风锁.md          38 行   静态出图的脸：配色 / 构图 / locked_prompt / seed
└── 动效音线锁.md     234 行   动态出片的脸：动效签名 / 转场 / 音线 / 片尾
```

**三条设计意图**：

1. **按消费时机切，不按内容切。** 静态脸在「调生图后端出一张图」那一刻被读，动态脸在
   「排分镜 / 写组件 / 铺音效 / 出片」那一刻被读。**两批消费者完全不重叠**——
   生图 agent 不需要知道转场决策表。切开之后，每一步只读一份、且必然读全。
2. **两者可以异步冻结。** 画风锁 `frozen: true`（整套已冻）；动效音线锁 `frozen: partial`，
   节内逐项标 ✅ / 🔧。写成一份就只能整体冻或整体不冻。
3. **动态脸是「会调的东西的家」，静态脸是「不许调的东西的家」**：
   > **「会调的东西的家」**：调质量 = 改本锁 → 反映到出片，不必每次翻 skill 代码。

## 判据文档怎么写才可执行：六种手法

这是本章最值得抄的一节。**把「风格」写成判据而不是形容词**，靠这六种手法：

### ① 把形容词换成有 / 无的二值判定

不写「别抖太厉害」，写：

> 本频道对「抖」的定义只有一句：**一切没有终点的周期变化都读作抖**——它不看幅度，
> 因为幅度只决定它多难被指认、不决定它在不在。
> （本频道为此翻过三次车，三次的处置都是「把幅度再降一档」，于是三次都复发。）

### ② 给分档表，每档配处置

| 档 | 什么样 | 判 |
|---|---|---|
| ① 有终点的动作 | 入场 / 落定 / 一次性形变 / 落定后的阻尼余波 | ✅ **允许，而且是主力**。「动完干净停」说的是它必须停，不是不许回弹——只要**收敛**，回弹几下都不算抖 |
| ② 无终点、但刻意让人看见且承载表意 | 手作抖边 / 加载转圈 / 表示「在运转」的齿轮 | ⚠️ 分镜里**逐镜点名**，一镜至多两处（与机检 `quality.perpetualSitesMax` 对齐）。**没点名 = 禁止** |
| ③ 无终点、且刻意让人看不见 | 全屏亮度脉动 / 亚像素恒速漂移 / 幅度 ≤1% 的呼吸 | ⛔ **一律禁止，无豁免**。这一档存在的理由只有一个：**骗过某道闸** |

### ③ 给可量的口径

> **「有终点」是量出来的，不是写出来的**：一段周期算收敛，要它开着的那段窗口**解得出数**、
> 且**不超过镜长的一半**；解不出来的（上界写成大数）一律按无终点算。
> 再加一条：一个组件里所有被放行的有界周期**并起来不许超过镜长的 60%**——
> 十二段各自都会停、首尾接起来照样从头抖到尾，那是同一件事拆成十二笔写。

### ④ 给可 grep 的静态检查项

质量门那一节整行都是复选框：

> ☐ 无 `Easing.linear` 裸入场 ☐ 无 `scale(0)` 起始 ☐ 出场没有对称复用入场曲线
> ☐ 每镜 expressive ≤1 ☐ 无终点周期动画逐条对得上第 ② 档（`Math.sin(frame` / `% 360` grep 得到）
> ☐ 两个环境层文件里**搜不到 `useCurrentFrame(`**

### ⑤ 写清楚失败长什么样——尤其静默失败

这一类是判据文档里信息密度最高的：

> ⚠️ **认不出的转场 kind 静默回落成 `fade`**，不报错不警告——**拼错一个字母和写对的表现完全一样，
> 只有抽帧看画面才发现**。
>
> ⚠️ 字幕的 `stroke` 是**一路传下去的，不是渲染器的默认**。从卡出发，经调用参数写进字幕轨，
> 再由渲染器读出来。**中间任何一跳漏掉，下游都会用自己的缺省值接住**——不报错、不掉帧、
> 客观质检全 PASS，只是画面上那层底没了。所以字幕那一步收尾必须跑闸，它专门拦这一跳。
>
> ⚠️ 键名在两侧不一样——卡里 snake_case，组件里 camelCase。照着卡的键名往组件里写会拿到
> `undefined`，而 **`undefined` 作 CSS 颜色不报错、只是不生效**。

### ⑥ 优先做成结构性不可能，其次才写规矩

第 ③ 档装饰抖动不是靠自觉禁止的：

> 第 ③ 档的机制已在**卡内**拆掉（两个覆盖文件），这两个文件的不变量是
> **整份文件不出现 `useCurrentFrame` 调用**——**没有帧就没有周期运动，也就没有可以再调低一次的幅度。**

### 贯穿全层的那句元规矩

> **规范只写在文档里、闸里没有 = 没有。**

它的实例：某个亮度上限「卡里写了一年，没有任何一步在量它」，直到用户耳测点名，
一查全库 40% 超限——然后才配了闸。同源表述在策略文件里：「**改文档不产生检查，所以配这道闸**」。

## design token 防硬编码：四道防线

1. **值只在 `card.json`。** `tokens.dtcg.json` 明确把自己降级成「人读参照」：
   > 机器值的事实源是 `card.json`；本文件只讲『为什么 / 人读说明』……
   > 运行时只读 card.json、**不读本文件**——下方各 `$value` 仅为人读参照，**可能滞后**。
2. **组件层强制走 theme**：「组件里一律 `theme.colors.*`，**禁硬编码 hex，也别在文档里抄第二份**」；
   缓动同理——「**别抄 hex 一样抄曲线**」。
3. **派生而非复制**：CSS 变量文件由 card.json 派生（一个 derive 脚本），
   「card.json 改后重派生，**模板零改吃新值**」。
4. **机检兜底**：`quality.fontFamilyCoverageMin` ——把「有没有用 token」变成一个能量的比率。

连 HTML 概念动画的 CSS 变量块都带注释：`/* = tokens.dtcg.json·勿写死偏离值 */`。
生图侧则由卡统一注入正 / 负向提示词，分镜提示词明写「**逐字用，不要自由发挥**」。

`tokens.dtcg.json` 用 W3C DTCG 格式，**每个 token 的 `$description` 写的是「它扮演什么角色」
而不是「它是什么颜色」**：

```json
{
  "$ssot": "机器值的事实源是 card.json（brand.tokens）；本文件只讲『为什么/人读说明』…",
  "$extensions": { "frozen": true, "version": "<版本标签>", "frozen_at": "<日期>",
                   "supersedes": "<上一版·已废弃>" },
  "color": {
    "$type": "color",
    "ink":    { "$value": "#…", "$description": "主色：超粗黑大字 / 粗描边。**统治画面的『黑』**" },
    "paper":  { "$value": "#…", "$description": "米白纸底：留白 / 浅底封面。**手绘温度的来源**" },
    "accent-mint": { "$value": "#…", "$description": "品牌锐利强调 = IP 眼睛色（**signature**）" }
  },
  "space": { "$type": "dimension", "$description": "8px 基准栅格，所有间距取倍数", "1": …, "2": … }
}
```

配色的应用要点也是**色槽 + 角色 + 面积配额**，不是一张色卡：

> - **底**：米白纸（手绘温度）；分层用暖白。
> - **主角**：黑墨超粗大字 + 粗黑描边，**统治画面**。
> - **撞色块**：三色**按角色用、不均分**。
> - **signature（只点）**：某一色 = IP 眼色，仅给**一个**记忆点点睛，**绝不铺满**。

## 封面三层分工

封面套件的 `_doc` 字段本身就是规格说明：

> **三层分工：画风层 = 封面画风锁的 frontmatter（唯一事实源）· 版面层 = 本文件的
> `prompt_template` + `sizes` + `ref_images` · 内容层 = 每条内容自己的 `封面/cover.json`。**

带一套模板语法：

> `{键}` 取值（**尺寸档 > 本条内容 > 本文件**）· `{键|join:分隔符}` 把多行值连起来 ·
> `[[ … ]]` 里的键有一个是空就**整段丢掉**。

**封面有第二把画风锁**，与片内那把分工明写：「那份管片内画面，这份管封面。」
（两者的视觉语言可以不同——片内是扁平插画，封面是剪纸拼贴。）

复用性写在说明里：

> **新频道复用**：复制整个 `封面/` 套件 → 换风格提示词 / 品牌尾串 / 参考图 →
> 该频道 `card.json` 加 `cover.config` 钩子。**skill 一行不改。**

还有一条踩过的坑：

> ⚠️ 内容块里**不要写** `Brand palette: #hex...` 那一行——**会被图模型画成一张色卡图例**（踩过）。

## 发布配置：平台矩阵是这一层的核心

一份 JSON（165 行）+ 一份说明（118 行）。**两条铁律写在 `_doc` 第一行**：

> ① 没有可信出处的字段值恒为 `null`，**`null` 的意思是「没有尺子」**，消费方必须如实报
> 「这一项检不了」，**不许折叠成通过**；② **改值必须同时改 `provenance`**。

### 四段结构

```json
{
  "master": { "orientation": "landscape", "aspect": "16:9", "width": 1920, "height": 1080,
    "_doc": "唯一母版画幅，四平台共用。不做原生竖屏；投短视频平台时是这条母版本身或它的切片。" },

  "coverSizes": {
    "16x9": { "width": 1920, "height": 1080, "platforms": ["bilibili", "youtube"] },
    "3x4":  { "width": 1080, "height": 1440, "platforms": ["douyin", "xiaohongshu"],
              "safeAreaPx": { "top": null, "bottom": null } },
    "_doc": "封面按尺寸出、按平台关联——统一渲这几个画幅，各平台取它习惯的那张，
             不为每个平台单独造一张。像素值必须与封面套件的 sizes 一致。" },

  "platforms": { "bilibili": {…}, "youtube": {…}, "douyin": {…}, "xiaohongshu": {…} },
  "provenance": { …每个值的出处台账… }
}
```

### 三类字段严格分开

```json
"_doc": "limit* = 平台硬约束，超了被截断/被拒/失效，没得商量。
         sweet* = 本频道自己定的取值区间，超了是取舍不是错误。
         video 是「我们发给这个平台的交付规格」而不是「平台强制要求的规格」
         ——质检拿它比对交付片，抓的是渲染漂移。"
```

四平台各自声明的东西（值省略，看形状）：

| | bilibili | youtube | douyin | xiaohongshu |
|---|---|---|---|---|
| `video` 交付规格 | 1920×1080 16:9 | 同 | 同 | 同 |
| `durationLimitSec`（硬） | 18000（官方 api） | 900（官方 web） | 900（官方 api） | **null** |
| `durationSweetSec`（频道甜区） | 300–900 | 480–900 | 15–180 | 6–120 |
| `limitTitleChars` | 80 | 100 | **null**（三通道打架） | 20（二手） |
| 简介上限 | `limitDescChars: 250` | `limitDescBytes: 5000`（**字节不是字符**） | — | — |
| `limitTags`（条数） | **null** | **null** | **null** | **null** |
| 封面约束 | ≤5 MB · 最小 960×600 | ≤2 MB · 最小宽 640 | **null** | **null** |

### `provenance`：这份文件真正的创新

每条值挂一条出处，**四档 `level`（官方 / 二手 / 频道 / 待核）+ 三通道 `channel`（api / app / web）**：

```json
"platforms.<平台>.limitTagsTotalChars": {
  "level": "官方", "channel": "api", "url": "<官方文档>",
  "note": "「多个标签用英文逗号分隔，总长度小于 200」" },

"platforms.<平台>.limitTitleChars": {
  "level": "待核",
  "note": "三个数按通道打架，没有一个支持旧矩阵写的那个值：开放平台说 ≤1000（官方）·
           小程序接口说 ≤60（官方）· App 内实测 55（二手）。本频道是人手动在 App 里发，
           该用 App 那条——而 App 那条没有官方出处。" },

"_通道口径": "本频道由人手动在 App / 网页里发布（**绝不代点发布**），所以真正管用的是 app / web
             通道的上限。而能程序化查证的官方文档几乎全是 api 通道——两者经常不同。
             凡 channel=api 的值，都要当成「同一量级的参考」而不是「app 里的确切上限」。",

"_<某平台>整体": "它没有公开的发布 API 文档……规格只存在于登录后的界面里，只能人工实测。
                  **这一条不是「还没查」，是「程序化查不到」。**"
```

### 为什么是 JSON 不是表格

说明文件里记了那个直接催生这套设计的坑：

> 写成 markdown 表格，机器读不到，于是各处只能自己写一份——同一个数字散在四个地方，
> 改一处其余三处照旧。这个坑已经踩过一次：**某个样式决策写在文档里，能力读的是结构化字段，
> 读不到就落回默认值——而那个默认值正是文档明令淘汰的那个。**
>
> **`null` 不是缺省，是「没有尺子」。** 这条约束是结构性的：只要待核字段恒为 `null`，
> 「读不到就用默认值」在物理上就不可能发生。

### 一件事只声明一次（防双向真相源）

> **「哪个比例发到哪个平台」只在 `coverSizes[*].platforms` 里写一次。** 平台那一侧**没有**
> 反向的 `cover.sizes` 字段——同一件事正着写一遍反着写一遍，早晚有一边被漏改。
>
> **主页横幅不在这份文件里**：各平台横幅尺寸已经在卡的 `brandAssets.banners` 里按平台列着，
> 那是它的家。**别在这里再抄一份。**

「现在还有哪几格没有尺子」也不许抄清单，**从数据里现算**：

```bash
python3 -c "import json;d=json.load(open('platforms.json'));\
print('\n'.join(k for k,v in d['provenance'].items() if isinstance(v,dict) and v.get('level')=='待核'))"
```

### 发布物：一平台一份，表格化到复制粘贴即发

```markdown
# 发布 · <平台> — <标题>

> 看这一张就发：复制粘贴到投稿页。规格事实源 `<平台矩阵路径>`。发完把链接回填选题卡 frontmatter。
> **调性**：<这个平台的口径一句话>

| 项 | 内容 |
|----|------|
| **视频** | [母版](../../母版/master.mp4)（横屏 16:9 · <时长>） |
| **封面** | [<主封>](…) ｜ [<备用>](…) |
| **标题** | <标题> |
| **分区** | <分区> |
| **标签（总长≤N）** | a, b, c |
| **声明** | <原创声明口径> |

> **校验**：标题 37 字 / 上限 80 ✅ · 标签 7 个 · 总长 41 字符 / 上限 200 ✅ · 简介 194 字 / 上限 250 ✅
> **⚠️ 时长甜区**：<时长> 低于本频道该平台甜区下限 —— 硬上限内，可发。
> 上限出处：`limitTitleChars` / `limitDescChars` 均为**官方**（<出处>）
```

**一条版式铁律**：校验说明一律写在表**外**的引用块里，**不塞进表格单元格**。

## 素材库的命名与 sidecar

`素材库/` 与 `BGM音效/` 是**同一套约定的两个实例**：分类自治 + 每分类自带 `_meta/` sidecar。

### 三层命名

1. **管线契约名**（不能改）：卡的 `layout.cardAssets.pipelineFixedSounds` 声明的那几个文件名
   是管线自动取的固定名——**必须存在、换款也要保留这个文件名**。
2. **家族名 + 变体后缀**：`whoosh` → `whoosh-clean` / `whoosh-deep` / `whoosh-paper-big`…
   **基名 = 管线自动落点的那一件，带后缀的都是候选池。**
3. **sidecar 同名对应**：`_meta/X.json` 描述同层 `X.wav`——**名字对上即可、卡里不写路径**。

### sidecar 字段表标了「谁填」

| 字段 | 谁填 | 含义 |
|---|---|---|
| `type` / `source` / `original` | 机器 | 类型 / 来源渠道 / 原名 |
| `license` / `url` | 机器 | **授权（版权链·不能断）** |
| `prompt` | 机器 | 生成用提示词（生成件才有） |
| `rating` / `usage` / `note` | **人** | 喜好 / `reuse`·`reference`·`retired` / 备注 |
| `used_count` | 机器 | 被落进成片的次数 |

授权拿不准就**诚实标注**：`"license": "待确认·从参考视频扒·可商用性需复核"`。

### 分类级出图模板只写「画什么」，不写「什么风格」

```markdown
# <分类> · 出图 prompt 模板
> 出图前先读卡的画风锁——**风格锚在那里，本模板只填「画什么」**。
- 主体：<一句话（孤立主体·不带场景背景）>
- 底：**透明底优先**
- 风格：吃卡里的正向提示词（**勿在此另起炉灶**）
- 出图后：落本目录上层，并在 `_meta/<名>.json` 补 sidecar
```

## 复利闭环：三处强制回填

| 时机 | 回填到哪 | 判词 |
|---|---|---|
| 脚本步 | 金句库 | 「**这个频道的复利就在这一步。**」 |
| 审稿步 | 金句 / 有效标题机制 / 踩到的坑三路 | 「**不回填的复盘等于没做**——这个频道的复利全在这一步。」 |
| 出片后 | 质检记忆 | 「这是频道的**经验飞轮**：越用越检得出问题、不重犯旧坑。」 |

配一条**反复利的例外**（防同质化）：概念图解组件每条现写、骨架只复用不复用画面、范例库只看不抄。
**地基层放心复用，表意层一律现写。**

## 诚实优先于完整

这一层反复出现的一种写法，值得单列：

- **`null` = 没有尺子**，不许折叠成通过
- **未做完标 🔧、做完了才翻 ✅**；已退役的明写 ⛔
- **资产缺口写在 README 里**：「两根母题金句基本空缺……**别硬凑**」；
  「待沉淀（**诚实占位 · 暂无真货，别当已有**）……**不留空头支票**」
- **文档自标会过期**：「与源码不符时**以源码为准，并回填本文**；查不到的就是本文过期了」
- **被推翻的假设明着写成撤回**，不删

## 打包：`bundle.omit` 把「拿掉」写成「教你重造」

omit 掉的是**成品二进制**，留下的是**生成配方 + 工程文件 + 位置声明**：

```json
{ "path": "品牌套件/<IP目录>",
  "reason": "IP 形象保留全部权利，且动作帧序列对你也没用——你的 IP 不是这只猫。
             换成你自己的：brand.mascot 段里的 visualPrompt / i2vSubject / i2vStyle
             就是可照抄的生成配方。" }
{ "path": "品牌套件/片头片尾/<片头>.mp4",
  "reason": "成片带着作者的 IP 与 slogan。同目录的 scenes-片头.json 是工程文件，
             照它渲染成你自己的。" }
```

商店页的收尾一句概括了整个授权设计：**「方法拿走，脸留下。」**

## 八条设计约定（速查）

1. **哪些属于卡**，判据是「换频道时它会不会变」，不是「是不是资产」
2. **值只有一份，文档只讲为什么**；人读镜像必须自标「可能滞后」并写出对应卡键名
3. **按「谁在什么时刻读」分文件**，不按主题分；机器读 JSON + 人读 md 成对出现
4. **判据用那六种手法写**，形容词一律换成可判定的形态
5. **诚实优先于完整**：`null` / 🔧 / ⛔ / 缺口声明 / 自标过期
6. **token 四道防线**：值只在卡 → 组件走 theme → 派生不复制 → 机检兜底
7. **发布配置三类字段分开 + 每值挂出处 + 一件事只声明一次**
8. **复利写进流程**，同时给反复利留例外（地基复用、表意现写）
