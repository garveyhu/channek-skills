# 06 · 内容管理：四库、双轨进度、经验飞轮

> 这一章讲 `内容/` 那一区怎么运转。它不随卡分发，但**它的组织方式随卡分发**
> （`layout.sections` 声明了四个库的位置，脚手架会建出来）。

## 情报分层：按「问题」切，不按「格式」切

`1-情报库/` 下五层，判据是**每层回答一个不同的问题**——这样才不会记重、记错地方：

| 层 | 回答什么问题 | 性质 | 保鲜期 |
|---|---|---|---|
| `前沿雷达/` | **抓到了什么**（论文 / trending / 发布会的原始情报流水） | 高频流动 | 14 天 |
| `深读笔记/` | **一件事怎么讲清**（概念的深度拆解，一篇可喂多条内容） | 长青·复用 | 常青 |
| `信息差地图/` | **世界上什么没讲清**（客观认知缺口台账——选题母矿） | 长青 | 30 天 |
| `灵感库/` | **别人怎么讲**（swipe file：爆款 / 钩子 / 封面 / 结构拆解） | 参考 | 60 天 |
| `平台流量研究/` | **什么内容在各平台有流量 + 怎么剪** | 月度更新 | 30 天 |

> 那一列保鲜期不是摆设——选题步的第 0 个动作就是跑一个闸检查各源的断更天数。

数据流是一个闭环：

```
灵感库 + 信息差地图 + 前沿雷达  →  选题库（打分排期）
                                     ↓
                                 内容工作台（深度底稿取 深读笔记/）
                                     ↓
                            复盘的增量回流 → 信息差地图 + 深读笔记
```

> 有了这条闭环，内容就从「一次性消耗选题」变成**知识的复利积累**。

### 蒸馏与原始双层，raw 永不删

```
平台流量研究/raw-<YYMMDD>/01…12-<线名>.md   ← 12 条并行调研线的原始报告（数千行）
        ↓ 蒸馏
前沿雷达/<YYYY-MM>-<线名>.md               ← 分类归纳后的成品
```

蒸馏产物的 frontmatter **必带 `sources:` 回指原始**，并明写作业边界：

```yaml
---
captured: 2026-08-25
line: 前沿雷达 · 工程线
window: 2026-06 ~ 2026-08（各源线窗口不一，逐条注明）
sources: [raw-<YYMMDD>/05-…, raw-<YYMMDD>/06-…, raw-<YYMMDD>/09-…]
entries: 17
compiled_by: <模型>（情报库整理智能体，**不做新检索**，只从 raw-<YYMMDD> 提炼归类）
convention: 四段式（事实+数据 —— 中文圈现状 / 信息差 —— 受众该懂 —— 来源）。
            需求证据等级、口径提醒、存疑标注一律照搬源报告，**不洗白、不补数**
---
```

**「不做新检索、不洗白、不补数」写进 frontmatter**，是这一层的作业契约。
正文里的不确定性也要就地标注：`⟨不确定: 具体数字依配置而定，此为某篇技术博客的估算举例⟩`。

深读笔记的最后一节固定叫「**可做成内容的角度（喂选题库）**」——那就是它对下游的接口。

灵感库更进一步：它的结论节里带一条 `### 冲突护栏（研究建议 ≠ 全盘照收 · 已按本地踩坑账过滤）`
——**情报层自己会去读质检记忆再过滤**。

## 选题库：一份数据多个视图，绝不双写

`2-选题库/` 的边界铁律写在索引文件开头：

> 本表只装**未开题**的候选。题一旦实例化成内容目录，就**从本表删行**——其状态改由该内容
> `选题卡.md` 的 frontmatter 管，经视图呈现。
> **未实例化 → 本表；已实例化 → frontmatter / 视图**，互不重叠。

同一条边界在三个地方各写了一遍（索引 / 批次文件 frontmatter / 分发目录 README），措辞一致。

两层粒度：

- **索引层**（一行一题的七列表）：`题目 | 角度（信息差点）| 信息差 | 受众 | 时效 | 优先级 | 来源`
- **详情层**（批次文件，一题一个 `###` 块）：角度 / 钩子三件套 / 可带走物 / 打分 / 来源

批次文件末尾三节护栏值得抄：

- `### 撞车检查（与已发 N 条）`——本批 × 已发 × 关系三列表
- `### 本批明确避开的红海（调研线实证，别回头捡）`
- `### 存疑与待核（写稿前必须处理，不许直接当事实讲）`

批次 frontmatter 里有一条**开工前的情报闸**：

```yaml
intel_gate: <日期> 平台流量研究✅ / 信息差地图✅补行 / 前沿雷达✅补 <月份>
```

## 条目元数据：`选题卡.md` 的 frontmatter 是唯一真相源

AGENTS.md 手写块钉死了这一条：

> **元数据真相源是 `选题卡.md` 的 frontmatter**：状态 / 平台 / 发布回填 / 复盘数据都写在那里，
> `内容/4-运营复盘` 的视图从它读。推进时改 `status` + `step`，卡住填 `blocker`。

所有看板都是它的 filter + 投影，**看板文件里零内容数据**。例如发布日历里这条公式，
从 `url_*` 反推已发平台——「发布事实以工件为准」在视图层的实现：

```yaml
formulas:
  published_platforms: (if(url_bilibili, "bilibili ", "") + if(url_youtube, "youtube ", "")
    + …).trim().split(" ").filter(value != "")
```

frontmatter 里还有**五个归因标签**（`motif` / `form` / `funnel` / `timeliness` / `hook_type`），
复盘时按它们归因，下一批选题据此调配比。

## 进度是双轨的：两套都要写，管的不是一件事

这是最容易做错的一处。AGENTS.md 说得最清楚：

> app 的灯轨要显示「这条内容进行到哪」，而它自己只看得见**盘上有没有产物**——
> 「正在做」「做砸了」「有意跳过」「产出没落在约定位置」这四件事它一件都推不出来。

| | **灯轨进度**（机器） | **运营元数据**（人 / 视图） |
|---|---|---|
| 载体 | `.produce-status/<能力>.json` + **盘上工件本身** | `选题卡.md` frontmatter 的 `status` / `step` / `blocker` |
| 谁写 | `channek invoke channek.report-step`（running / done / failed / skipped） | 推进时手改 |
| 不写会怎样 | 落回**猜产物**（逐个 `test -f`）——**不报错，只是一直显示错的东西** | 无兜底 |

```bash
channek invoke channek.report-step entry="$(pwd)" step=<步key> status=running
channek invoke channek.report-step entry="$(pwd)" step=<步key> status=running progress=8/15
channek invoke channek.report-step entry="$(pwd)" step=<步key> status=done
channek invoke channek.report-step entry="$(pwd)" step=<步key> status=failed  note="没跑成，原因写这里"
channek invoke channek.report-step entry="$(pwd)" step=<步key> status=skipped note="这条不做这一步，原因写这里"
```

> `failed` 与 `skipped` **必须给 `note`**：一盏没有下文的灯，用户只能回头来问你。

**但「完成」的判据仍然是工件在不在，不是状态字段。** 这一条有硬证据：某条内容的 frontmatter
至今卡在 `step: 4` + `blocker: 重跑中`，而它一个多月前就发布了、盘上 200 多个工件全齐。
**手写状态机漂了，工件没漂。**

所以：**不写状态机，断点续跑天然成立**——从头扫一遍工件，缺哪步做哪步。

> 还有一份 `.pipeline-ack.json` 记「下游确认吃过上游哪一版」，用时间戳做脏检查——
> 上游变了下游就该重跑。这也是从工件推出来的，不是人维护的。

## 质检记忆：这个范式最亮的一块

### 两层：捕获在条目里，蒸馏在库里

| 层 | 位置 | 什么时候写 | 形态 |
|---|---|---|---|
| **捕获层** | `<条目>/出片问题记录.md` | 生产全程随手记 | 细账，带编号 |
| **蒸馏层** | `内容/质检记忆/踩坑账.md` | 验收后按根因归纳 | 压缩成一行 |

蒸馏层是**单文件、append-only**，frontmatter 只有三行但把策略写死了：

```yaml
---
type: 质检记忆 · 踩坑账（原始层）
策略: append-only·只增不改·每坑一条；蒸馏去向是**各闸的机器维度或 HUMAN_CHECKS**，
      不是另一份要人记得打开的清单
---
```

### 头部那段使用说明是整套机制的宪法

> **剪片时不读这里。** 这是溯源账，不是开工清单 —— 它只增不删，所以必然越来越长，
> **长本身不是病**。要你读的东西一直是另外两样：**skill 里的规约**（怎么做）和
> **跑闸的输出**（做对没有）。
>
> **一条坑的归宿只有三种，写进「反哺去向」栏：**
>
> | 归宿 | 意思 | 你什么时候会再见到它 |
> |---|---|---|
> | **成机器维度** | 变成某道闸里的一个 `check_*` | 每次跑那道闸，自动判 |
> | **进 HUMAN_CHECKS** | 机器判不了（遮挡 / 语感 / 审美），塞进对应闸的人工清单 | 每次跑那道闸，自动**打印**在末尾提醒你 |
> | **留在引擎侧** | 根因在引擎，卡里改不了 | 引擎那边修；本账只留证据 |
>
> 所以「固化」的验收标准不是「记下来了」，而是
> **这条坑能不能在不看本账的情况下被再次拦住**。
>
> **只在三种时候翻本账**：① 装一道新闸、想知道这类坑历史上什么形态
> ② 成片翻车、要定位是不是老坑复发 ③ 清账。

字段：`阶段 | 现象 | 根因 | 修法 | 反哺去向 | 状态`
状态三档：**🟢 已成闸** · **🔴 未固化**（还只是一段文字，下一片照样会踩）· **⬜ 已撤回**（判据本身是错的）

### 三条最有代表性的记忆

**① 元反思型：「记了不修 = 白记」**

> | 阶段 | 现象 | 根因 | 修法 | 反哺去向 | 状态 |
> | **方法** | 同一个坑记过又犯：某条根因栏已写「该加什么闸」、状态 🔴，**一个半月没落地**，于是原样复发 | 踩坑账**只记不修 = 白记** | 本轮一并落地 | **每条 🔴 的反哺去向要么当场落地、要么明确记为待办并排期**；只写在账上不进闸的规范，等于没有 | 🟢 |

**② 闸本身也会坏**

> | **闸本身** | 新写的某道闸**装上就空转、报 PASS**，而画面上真压着字幕 | 预处理把**字符串字面量**也抹白了，而判据要找的东西恰恰是字符串 —— 正则永远匹配不到 | 改成只抹注释、保留字符串；第二版仍有 3/4 误报，最终换成语法配对栈 | **写闸必须先验它抓不抓得住已知的那几处**：拿本期当回归样本跑，**报 PASS 就是闸坏了不是片好了** | 🟢 |

**③ 撤回（判据本身是错的）**

> | 组件/配色 | 底色太黄 | 统计说撞色密度塌了 | 待落：撞色密度下限 | **已撤回**：统计只数了一种写法漏了同义写法，判据本身是错的；skill 里写了撤回说明，不再装闸 | ⬜ |

**⬜ 这一档很关键**——被推翻的假设**明着留在账上标成撤回，不删**。删掉的话，下一个人会重新发现一遍。

### 它怎么被后续创作利用：三次转写，账本身不进上下文

```
翻车 → <条目>/出片问题记录.md（细账）
     → 踩坑账.md 一行（现象 / 根因 / 修法 / 反哺去向 / 状态）
     → 「反哺去向」指向的三种归宿之一
     → 下一条片开工时，读的是 skill 规约 + 跑闸的输出，**账本身不进上下文**
```

配一个对账器（`reconcile_ledger.py`）逐条比对，把「记了没修」和「修了没销账」揪出来。

**闸生效的正面证据也记账**：某条记着「顺手写了个看起来该有的图标名 → 新装那道『图标名』闸当场抓到」。

### 沉淀出的九条通则

散在账里的引用块是最高层的抽象产物，每条都可以直接搬进别的频道：

| # | 通则 |
|---|---|
| 一 | **脱敏**：真材料不只要「真」，还要「能公开」，且必须在**落库那一刻**处置 |
| 二 | **节奏**：镜长呼吸 = 句子功能分工——判词句短到能被单独记住，解释句才铺长 |
| 三 | **payload 边界**：给渲染的字段里每个字符串都可能出现在观众眼前；实现说明写注释或 sidecar |
| 四 | **脱敏落层**：脱敏落在**素材**上不落在**组件**上（落组件闸拦不住也帮不了） |
| 五 | **停顿是内容**：「像 PPT / 像拼接」有可测形态——中位空档太大 + 起伏变异系数太小 |
| 六 | **判据的锚**：别拿好结果的特征当判据的锚（问一句「这个锚，在已经修好的状态下还成立吗？」） |
| 七 | **阈值要配闸**：卡里声明一个阈值 ≠ 有人在量它。加阈值时问「**谁读它？**」读不到就别加，加了就配闸 |
| 八 | **保质期**：「这个机制是断的」是有保质期的话，写它时必须附一条可执行的复核方式 |
| 九 | **报数带口径**：「多大 / 多快 / 多少条」说之前先问「量的是哪一层」 |

**通则七是整套范式的浓缩**——卡的 `config` 段能声明任意阈值，但**声明本身不产生检查**。

## 复盘回流：两条闭环，诚实地说一条是断的

| 闭环 | 触发 | 载体 | 归宿 | 实况 |
|---|---|---|---|---|
| **质量闭环** | 每次验收 / 用户反馈 | 出片问题记录 → 踩坑账 | 机器闸 / HUMAN_CHECKS / 引擎侧 | ✅ **跑满**：78 条坑、多轮迭代、多道闸落地，还长出「装闸契约」这类元规约 |
| **运营闭环** | 发布后 T+7 | 待填数据 → frontmatter → 视图 → 反哺信息差地图 | 下一批选题的证据 | ⚠️ **断的**：24 条已发布、**0 条 reviewed**、数据列全空 |

**两条闭环的设计是对称的**（发现 → 记账 → 归宿 → 下一轮读到），差别在：

> **质量闭环的归宿是可执行的脚本，运营闭环的归宿是要人手抄的数字。**

这恰好又是通则七的一个实例。**复刻这套时，别只抄跑得通的那条**——把运营闭环也接上可执行的东西，
或者诚实承认它靠人、给它排期。这个频道自己在批次文件里就是这么承认的：
「补上自家播放数据是下一批最该做的一件事」。

## 十条设计约定（速查）

1. **库分层按「问题」切**，不按格式切；编号即流水线顺序，横切的库不编号
2. **蒸馏与原始双层，raw 永不删**；蒸馏产物必带 `sources:` 与「不补数」的作业契约
3. **条目名 `<YYMMDD>-<slug>`，date 是开题日**；不在别处建内容目录
4. **产物落点全部由卡的 `layout.artifacts` 声明**，找不到先问卡不要猜
5. **目录骨架刚性，空目录也留**
6. **一份数据多个视图，绝不双写**；视图文件里零内容数据
7. **进度双轨**：灯轨报状态 + 工件定完成；**不写状态机**
8. **证据与生成物理分区**；真材料缺位诚实降级，绝不生成顶替
9. **频道级复用 vs 本条独有物理隔离**；地基层复用，表意层每条现写
10. **翻车必须有归宿**：三选一（机器维度 / HUMAN_CHECKS / 引擎侧），只记不修等于白记

## 自检

- [ ] 情报库每一层都能一句话说清「它回答什么问题」，且不与另一层重叠
- [ ] 选题的状态只有一处真相源，未实例化和已实例化互不重叠
- [ ] 所有看板 / 视图都是 frontmatter 的投影，里面没有内容数据
- [ ] 推进内容时**两套进度都写了**（report-step + frontmatter）
- [ ] 没有任何 `state.json` 之类的状态机
- [ ] 踩坑账里每条 🔴 都有排期，没有一条挂了一个月还是 🔴
- [ ] 被推翻的判据标了 ⬜ 留在账上，没被删掉
- [ ] 问一遍通则七：卡里每个阈值，**谁读它**？
