# 04 · 方法论层：prompts / docs / skills 三件套

> 一张只有 `card.json` 的卡，是把方法论留在了作者脑子里。
> 收卡人拿到配置、拿不到「这个频道怎么做内容」——他会照着自己的习惯做，做出来不是这个频道的东西。

## 三件套的分工（先记这一句）

**prompts 喂给流程里的某一步，docs 喂给整个 AI 层，skills 喂给用户自己的 Agent。**

| | 放哪 | 读者 | 形态 | 卡里怎么登记 |
|---|---|---|---|---|
| **prompts** | 卡内 `prompts/` | 某一步的模型 | 作业指令（纯文本） | `prompts` 段，键→卡内相对路径 |
| **docs** | 卡内各处 | 整个 AI 层（注入上下文） | 判据文档 | `layout.cardAssets.docs` 的 8 个挂载点 |
| **skills** | 卡内 `skills/` | 用户自己的 coding agent | 操作手册 | `layout.cardAssets.libraries.skills` |

**三者互相引用、绝不复制。** skill 引用 prompts，不抄一份判据进来——抄一份就是第二个真相源，
改一处忘一处。

> app 只负责把 skills 摆到频道根 `.claude/skills/`（软链回卡），**它本身不执行 skill**。
> 读它、按它办事的是用户自己的 Agent。同名时卡里的优先。

## skills 的三层结构

飞轮日记的 `风格卡/skills/` 是 **16 个目录 = `_shared` + 15 个 skill**：

```
风格卡/skills/
├── _shared/                 ← 接口契约层（没有 SKILL.md，不是可触发的 skill）
│   ├── 读卡与调能力.md        两条接口：怎么读卡、怎么调能力 + 本频道取值速查表
│   └── 装闸契约.md            元规约：往任何 check_*.py 加判据时的验收规矩
├── produce-flow/            ← 编排层（总编排：交接链 / 顺序约束 / 退回定位）
│   ├── SKILL.md
│   └── reference/退回定位.md
└── <每一步>-craft/          ← 方法论层（15 个单步 skill）
    ├── SKILL.md               判据与入口（不看就会做错的东西）
    ├── reference/             深度内容外挂（可看可不看的一律放这）
    └── scripts/               这一步的可执行闸
```

三层各解决一个**必然会出现**的问题：

| 层 | 解决什么 | 不这么分会怎样 |
|---|---|---|
| `_shared/` | 「怎么取值 / 怎么调能力 / 怎么装闸」对 15 个 skill 完全一样 | 写 15 遍，改一次要改 15 处，改漏就出现两份互相矛盾的说明书 |
| 单步 skill | 「这一步怎么做对」 | 方法论无处安放，每次对话现讲一遍 |
| `produce-flow` | 交接物清单 / 顺序约束 / 闸挂哪个交接口——**这三类知识不属于任何单步** | 写进单步就会变成两份，下游那份永远滞后 |

**引用是单向的**：单步 skill → `_shared`；produce-flow → `_shared` + 指派单步。
`_shared` **不反向引用任何 skill**，保持零依赖。

### 一条贯穿三层的元原则：单一真相源

卡是数值的真相源 → `_shared` 是取值方式的真相源 → 单步 skill 是判据细节的真相源 →
produce-flow 是顺序与交接的真相源。

**任何一层重复持有另一层的内容都被显式禁止**：produce-flow 不抄闸参数、质检 skill 不抄平台规格
（「抄一份出来就等着两边对不上」）。

## `_shared/读卡与调能力.md`：整套范式的地基

这一份决定了其余 15 份能不能写对。骨架只有三节：**读卡 · 调能力 · 硬禁止**。

### 读卡

```bash
channek card <点号路径>       # 取一个值
channek card layout.artifacts # 取整段（键里带点的用这个，别拿点号去钻）
channek root                  # 频道根路径
```

**最关键的一条：工件只说语义 id，不说文件名。**

> 每一步的产物在哪，由卡的 `layout.artifacts` 回答：键是语义 id，值是相对内容目录的路径。
> 所以 skill 里出现的永远是语义 id（`channek.script` / `channek.master`），**不是文件名**。
> 换一张目录结构不同的卡，同一个语义 id 会指向别的路径——**写死文件名的代码在那里当场瞎**。

这一节还带一张「哪个键 / 干什么 / 谁用」的**本频道取值速查表**，让 15 个 skill 不必各自去翻卡。

结尾一条踩坑级警告值得照抄形态：

> **别把卡里的量互相套用。** 典型的坑：配速（含首尾静音的整体值，写稿用）和分镜估时用的
> **纯说话速率**是两个量，后者必然更高——互套会让镜比配音长出好几秒的静等死时间。

### 调能力

```bash
channek caps                                  # 有哪些能力、谁提供、缺的给人话提示
channek cap <能力id>                          # 这条能力吃什么参数（★ 调之前先问它）
channek invoke <能力id> 参数=值 --out <目录>   # 调一条能力
```

**id 写死，参数不写死——两个方向是相反的**：

- **能力 id 要写出来。** 它是稳定契约。skill 里写 `<语音合成能力id>` 这种占位符，等于让读者
  去中文标签里猜——频道里有好几条音频能力时必然猜错。
- **参数表永远不写。** 能力会演进，写死的说明书当天就开始过期。

**结果契约**（stdout 末行一行 JSON，进度日志在 stderr）：

```json
{"ok": true, "path": "/abs/out.wav", "type": "audio", "backend": "...",
 "attempts": [{"backend": "...", "status": "ok|failed|unavailable", "error": "..."}]}
```

退出码：成功 `0` · 能力不可用 `3` · 调用失败 `1` · 用法错误 `2`。
`attempts` 会如实列出每个候选为什么没用上——**回退不掩盖失败**，别把「降级跑通了」当成功汇报。

**能力缺了怎么办**（被所有单步 skill 反复回指的一段）：

> - 停在这一步，如实记账（缺哪条能力、卡在哪一步、装什么能续）。
> - **不许用别的手段顶替**：不写 ffmpeg / python 脚本自己干、不找外部工具、不拿生成内容冒充。
> - 后续步骤**不依赖**这条产物的可以继续；依赖的，一律不往下走。

### 硬禁止（五条，一字不改可抄）

> - ❌ 在 skill 里写死任何工件文件名——说语义 id，让读者去读卡。
> - ❌ 在 skill 里写死配速、采样率、行宽、阈值——读卡。
> - ❌ 在 skill 里写某条能力的参数表——`channek cap <id>` 问它。
> - ❌ 绕过 `channek invoke` 直接调 ffmpeg / python / 外部脚本干活。
> - ❌ 引用本机绝对路径、或频道目录以外的任何东西。

## `produce-flow`：编排层写什么

四样东西，都是**跨步的、不属于任何单步的**知识：

**① 交接链表**——每步一行：`吃什么 / 交出什么（语义 id + 交接物）/ 这一步的 skill`。
「交出什么」这一列是命门。注意两个设计：

- 一步可以**对应多个 skill**（分镜 = storyboard → component / html；剪辑 = sound → edit → qc）。
- 不在流程里的步要**明确标出来**（复盘 skill：「不在九步里，但选题打分靠它才会变准」）。

**② 顺序约束**——写法是「断言 + 反过来会付出什么代价」，不解释原理只讲后果：

> 配音在剪辑之前。镜长必须按真实旁白音频时长定死，再去渲。反过来要全片重渲一遍，
> 而且中间必然出现「画面早演完、静等念稿」的死冻。

**③ 闸挂在哪个交接口**——这是编排层最容易被做反的一件事：

> **闸不是那一步 skill 的私事，是这条链的交接条件。** 不跑、或跑了不绿就往下走，下游拿到的是
> 「结构完好、退出码 0、画面不对」的东西——那一类问题只有渲完抽帧才看得见，代价是整片重来。

闸的**脚本住在单步 skill 里**（判据细节归它维护），但**「什么时候必须跑它」归编排**。
编排里**不抄参数**：「抄一份就是第二个真相源，脚本加个开关它当天就开始骗人。」

**④ 退回定位**——外挂到 `reference/退回定位.md`。它的通则是整套范式的方法论内核：

> **问一句：这个缺陷是在哪一步被「决定」的？**
> 画面长什么样——分镜决定的。画面渲得对不对——剪辑决定的。
> 声音说什么——写稿决定的；怎么念——配音决定的。
> 屏幕上显示什么字——写稿决定的（字幕只是把它对上时间）。
>
> **修在「决定它」的那一步，不在「暴露它」的那一步。** 在下游打补丁（撒颗粒盖死帧、
> 剪音频盖错字、拿生成图盖缺素材）**每一次都是把问题埋深一层**。

配一张成本梯度图：

```
选题 → 写稿 → 分镜 → 素材 → 配音 → 字幕 → 剪辑 → 封面 → 发布
 ← 便宜 ─────────────────────────────────────── 贵 →
```

## 单步 skill 的通用骨架

**可填空的模板见 [`templates/step-skill-skeleton.md`](templates/step-skill-skeleton.md)。** 这里只讲几个决定质量的写法。

### SKILL.md 的篇幅 ≈ 这一步的返工代价

飞轮日记的实际分布（行数）：分镜 387、组件 727 —— 这是「改在这里最便宜、错在这里最贵」
的两步；剪辑 94、封面 98、发布 105 —— 几乎只是「顺序 + 禁忌」的薄壳。

**别为了对齐而把每份写成一样厚。** 深度内容外挂到 `reference/`，SKILL.md 里出现的一定是
「不看就会做错」的。

### description 写四段，触发词要写「症状」

```yaml
description: >-
  写口播稿——把一张选题卡打磨成一篇给耳朵听的、让人想知道下去的讲述。
  当用户要「写脚本 / 写口播稿 / 脚本怎么开头 / 开场留不住人 / 脚本太水太平 / 改稿去 AI 味」时使用。
  管三件事：……
  边界：不做选题（上游）、不排画面不选图解范式不画分镜（下游）。
```

四段：**是什么 → 何时触发 → 核心原则 → 边界**。

触发词的关键在于**故意混入症状式的说法**——不只是「想做 X」，还有「X 做砸了」
（「开场留不住人」「脚本太水太平」「配音听着不对」「片子像 PPT 一样干」）。
用户求助时说的是症状，不是能力名。

### 「吃 / 产」三行块，永不出现文件名

```markdown
**吃**：卡的 `channek.entry`（选题卡）。
**产**：卡的 `channek.script`（口播稿），内含**钩子卡**与**概念清单**两份交接物。
参数与路径读卡：[`../_shared/读卡与调能力.md`](../_shared/读卡与调能力.md)。
```

语义 id 用反引号 + 括号补中文。几个变体值得知道：

- 输入可缺 → 标 `（可缺）`
- 产物不只是新文件 → 「以及**每镜定死的镜长**写回分镜」（**可以是对上游工件的原地修改**）
- 产物不是文件 → 「一份判定（PASS / FAIL + 逐条结果 + 定位到哪一步）」

### 阈值由 shell 内联读卡传入，脚本不带默认值

```bash
python scripts/check_script.py <稿件路径> --cps "$(channek card channek.voice.pace)"
```

这一行是范式的缩影：**换一张卡，闸自动换一把尺子。** 脚本里写默认值 = 卡失效了还在拿旧尺子量。

### 「什么算合格」的三条写法规矩

- 机器判得了的，写「跑 xxx 闸，🔴 项清零才算过」——**别用眼睛复判机器能判的**。
- 机器判不了的逐条列，每条配一句**「怎么自证」的操作法**
  （「把比喻单独讲给人，问『照这该怎么解决』，答反了就换」）。
- 至少一条**把机器指标翻译成观众会说的那句话**
  （「呼吸 CV < 0.45」= 「观众会说切换生硬 / 像拼接 / 像 PPT」）。

### 「出问题怎么办」是一张往上游路由的表

两列或三列：`症状 / 退回哪一步 / 为什么是它`。第三列是关键——它给判断依据而不只是结论。
表后常配一条**反模式警告**：

> 给长 hold 撒颗粒、加微动去骗过死帧检测 = 治标不治本，带颗粒的冻结还是冻结。死冻的根在分镜，回去拆。

### 半级编号：后补经验插进已有编号，不重排全文

`## 2.5` `### 3.5` `### 7.6` 这类编号在飞轮日记里到处都是。写法是：
**先写「错的做法 + 它造成过什么后果（带具体事故）」，再写正确做法。**

> **逐幕各调一次 TTS 是错的做法。** 一次调用起一个新进程，本机那家会把 ~3GB 的模型重装一遍；
> 15 幕就是装 15 次。再开几条并行去抢时间，几个 3GB 同时躺在内存里——**这台机器被这么顶到过内核 panic**。

### 硬禁止的固定格式

`❌ **[动作]**——[为什么错 / 它造成过什么]（§引用）`

至少覆盖六类：① 写死本该读卡的值；② 绕过能力自己写脚本；③ 跨界干上下游的事；
④ 只看退出码不看产物；⑤ 相信自我汇报；⑥ 这一步特有的那三五个坑。

## `_shared/装闸契约.md`：给闸加判据的元规约

**一维新判据不是「写完跑一遍新片全绿」就算装好了。** 全绿有三种可能：真的合格 · 判据空转
（什么都没查到）· 判据查错了地方。**只跑一次分不出是哪一种。**

两步验收，缺一不算装完：

**① 反向验证**——**故意造一个违规，确认闸真的会响**。

```bash
# 例：给分镜里塞一个不存在的图标名，确认「图标名」这一维会响
python - <<'PY'
import io, json
d = json.load(io.open("<产物>.json", encoding="utf-8"))
d["data"]["scenes"][3]["payload"]["props"]["rules"][0]["icon"] = "check"   # 真表里没有
io.open("/tmp/bad.json", "w", encoding="utf-8").write(json.dumps(d, ensure_ascii=False))
PY
python check_storyboard.py /tmp/bad.json … | grep 图标名     # 必须出现 ⚠️
```

> **不报 = 判据空转，白装。** 已经发生过两次：一次是预处理把字符串字面量也抹白了，
> 而判据要找的东西**本身就是字符串**；一次是某个查表取不到值只拿到 `undefined`、
> 不报错不崩，画面静默空掉，**渲完才看得见**。

**② 历史回归**——拿旧内容跑一遍，分清「真债」还是「误报」：

- 真债 → 这一维进日期门（`quality.gateSinceDate`），只对新内容拦、对旧的 WARN。
  **别为了让旧片变绿而放宽判据。**
- 误报 → **修判据口径，不是加例外。加例外是把误报藏起来。**

**判据口径的四个通病**（这张表可以直接抄进任何频道）：

| 偷懒写法 | 为什么错 | 该怎么写 |
|---|---|---|
| 前后 N 字符窗口 | 密排代码里必然跨对象串味 | 按语法结构切（大括号配平 / 标签配对栈） |
| 正则直接扫源码 | 注释、字符串字面量里的同形文字会误命中 | 先剥注释；**但别连字符串一起剥** |
| 缩进猜层级 | 格式化工具一换行就崩 | 用配对栈判祖先关系 |
| 只统计一种写法 | 漏掉同义写法 → 统计结论是假的 | 先把「同一件事有几种写法」数清楚再统计 |

**文档回写义务**：新装的维度要在对应 skill 正文里写清**判据是什么、红线值哪来的、
已知盲点是什么**。只有代码没有文档，下一轮就会有人为了让它变绿而把代码改歪。
数值型红线要写出来源（「830 来自三个基线组件实测 827/830/830」）；
**拿不出数据支撑的假设明着写成撤回**，别留在文档里冒充判据。

## 五条隐形规约（写 skill 时最容易漏的）

1. **凡是数值，必须能追到卡里的键**，且在 skill 正文里明写这个键名；脚本不带默认值。
2. **凡是文件路径，只写语义 id**。确实需要贴一条可粘贴运行的命令时，写字面量并**当场加免责**：
   「上面把它们写成字面量只是为了能直接粘贴——换一张卡就得重新解析，别把它当常量」。
3. **举例必须标日期与条目名**，并注明它是**当前取值 / 实测读数、不是常量**。
4. **被推翻的假设明着写进正文，标成「撤回」，不删**——否则下一个人会重新发现一遍。
5. **深度内容外挂到 `reference/`**，SKILL.md 只留判据与入口。

## 六条范式指纹（浓缩版·可直接拿去自检）

1. **语义 id 取代文件名**——skill 里永远写 `channek.script`，永远不写 `脚本.md`。
2. **能力 id 写死、参数永不写**——`channek cap <id>` 现问；换后端不改 skill。
3. **闸挂在交接口，不挂在步上**——阈值由 shell 内联读卡传入，脚本不带默认值。
4. **装闸要过两步验收**——反向验证 + 历史回归，缺一不算装完。
5. **进度 = 工件在不在**——不写状态机，断点续跑天然成立。
6. **修在「决定它」的那一步，不在「暴露它」的那一步**。
