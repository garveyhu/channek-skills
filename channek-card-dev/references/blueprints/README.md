# 样板频道（blueprints）

**卡的字段表告诉你「怎么写才合法」，这一册告诉你「写成什么样才好用」。**

一张合法的卡 + 一堆装好的插件，不等于一个能持续产出的频道。差的那部分——目录怎么切、
判据写在哪、方法论怎么随卡走、翻车的经验怎么变成下次拦得住的闸——没有 schema 管，
只能看跑通过的频道长什么样。

## 怎么用这一册

1. **先看下面的对照表**，找到与你媒介 / 规模最接近的那一列。
2. **深读 [`flywheel-diary/`](flywheel-diary/)**——它是唯一被完整拆开的样板，
   七章覆盖目录、卡配置、说明书、方法论、脚本闸、内容管理、风格与发布。
   即便你做的是图文或播客，**② ③ ④ 三章的做法是通用的**。
3. **照 [复刻清单](flywheel-diary/README.md#复刻清单从零到第一条内容) 走**，每一步都指得到章节。

> **样板不是模板。** 里面的数值、色板、提示词是那个频道的身份；
> 你要抄的是**结构、命名约定、判据的写法、诚实标注的习惯**。

## 四个真实频道的对照

同一个作者，同一套内核，四种媒介。**成熟度诚实标注**——脚手架和实战频道不能混着看。

## 三条可以直接搬走的结论

### ① `layout.sections` 的四个 id 是内核级的心智骨架

四个频道用的是**同一组语义 id**，只是文件夹名换了行话：

| 语义 `id` | 飞轮日记 | 比奇堡 | 夜话（播客） | 工具笔记（图文） |
|---|---|---|---|---|
| `intel`（选题原料） | `内容/1-情报库` | `内容/4-参考拆解` | **`听友来信`** | **`摘抄`** |
| `topics`（选题库） | `内容/2-选题库` | `内容/1-选题库` | `选题池` | `选题箱` |
| *(contentDir)* | `内容/3-内容工作台` | `内容/2-内容工作台` | `节目` | `文章` |
| `review`（运营复盘） | `内容/4-运营复盘` | *(无)* | `数据复盘` | `发布记录` |
| `qc`（质检记忆） | `内容/质检记忆` | `内容/3-质检记忆` | *(无)* | *(无)* |

写对 id，AGENTS.md 才会渲成中文说明；`path` 随你起。

**同一个槽位的用途会随媒介和阶段变**：播客的 `intel` 是听众投稿（「这档节目一半的选题来自来信」），
第二个视频频道的 `intel` 是对标片的定量拆解。**没发过内容的频道干脆不声明 `review`。**

### ② 九步是超集，其它形态靠「抽步 + 借步」

| 内核步 | 飞轮日记 | 比奇堡 | 夜话 | 工具笔记 |
|---|:--:|:--:|:--:|:--:|
| `topic` | ✅ | ✅ | ✅ `topic` | ✅ `topic` |
| `script` | ✅ | ✅ | ✅ `outline`（**提纲**） | ✅ `draft`（**正文写作**） |
| `storyboard` | ✅ | ✅ | — | — |
| `asset` | ✅ | ✅ | — | —（配图不占步） |
| `voice` | ✅ TTS | ✅ TTS | ✅ `record`（**真人录音**） | — |
| `caption` | ✅ 屏幕字幕 | ✅ | ✅ `transcript`（**公开逐字稿**） | — |
| `edit` | ✅ 视频轨 | ✅ | ✅ `cut`（**纯音频轨**） | — |
| `cover` | ✅ | ✅ | — | —（头图并入配图） |
| `publish` | ✅ | ✅ | ✅ `release` | ✅ `submit` |

两张轻卡的 README 都主动解释了这层「借步」，措辞几乎同构——**这是被有意识设计过的，不是凑合**：

> 03 和 04 两步的显示名来自出片流程插件（**它是给视频频道写的**）。这档节目把「配音」用作录音、
> 把「字幕」用作逐字稿——**语义在这里，别被名字带跑**。

同一个 `step` 在不同媒介里是不同的事：`channek.voice` 在视频里是 TTS 合成，在播客里是真人录音 + 降噪。

**播客卡还独有一个 `editor.trackTemplate`**，把同一张剪辑台换成纯音频形态（主轨 / 嘉宾 / 片花 / 底床）。

### ③ 方法论有三条承载路线，按媒介选

| 路线 | 谁在用 | 载体 | 适合什么 |
|---|---|---|---|
| **A · 轻承载** | 夜话 · 工具笔记 | prompts（3–4 份）+ `docs.charter`（写作 / 录制守则）+ `config` 三档分组（33–34 字段）+ 各容器 README | 复杂度在**判断力**上、**没有机械工序**的媒介（文章、播客） |
| **B · skill 承载** | 飞轮日记 · 比奇堡 | `skills/`（`_shared` + `<step>-craft` + `produce-flow`）+ 自研闸 + `风格锁/` | 复杂度在**工序编排 + 能力调用**上的媒介（视频） |
| **C · 手写块承载** | 飞轮日记 | `AGENTS.md` 的 `channek:end` 之后 + `质检记忆/` | 托管块装不下、又不值得单开 skill 的**运营级经验** |

三者不互斥（飞轮日记三条都用），但**只有跑过内容的频道才会长出 B 和 C**。

**`skills/` 是视频频道特有的负担。** 图文 / 播客不需要它——skill 是用来包装「调哪条能力、
传什么参数」的；这两类媒介的复杂度全在判断力上，用 prompts + charter + config 三件套就够。

轻量频道那条路线里，**`config` 段才是真正的可执行方法论**。它把「skill 里会写的规矩」
编码成结构化配置，再由 AGENTS.md 喂给 AI：

```json
{ "key": "tone.banned", "name": "忌用词", "type": "text",
  "hint": "写完通读一遍，命中就改写整句，不是替换词",
  "value": "赋能, 打造, 一站式, 全链路, 闭环, 干货满满, 建议收藏, 划重点, 颠覆, 神器" }
```

轻量频道的 `docs.charter`（写作守则 / 录制守则）开篇都写着同一句分工声明：

> 设置页里那些开关是给机器看的，这份是给人看的。**两边冲突以这份为准，然后回去把开关改对。**
