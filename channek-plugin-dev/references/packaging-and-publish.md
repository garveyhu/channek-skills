# 打包、签名与发布

## 命名空间：`<publisher>.<name>`

- 只有第一段需要中央权威：`<publisher>` 全局注册（绑 GitHub 账号）、大小写不敏感、
  只允许 `[a-z0-9-]`；第一段之后归作者自己管，可以再带点（`acme.media.remotion` 的
  publisher 是 `acme`）。
- **`channek.*` 保留给第一方**，注册表拒绝第三方注册。
- **id 是不可变主键**：发布后永不改名——卡的 `requires` 指着它、设置与插件存储按它建键。
  要改名 = 发新插件 + 老的标弃用。

## 打包：只用官方 pack，绝不手工 zip

```bash
channek plugin pack <插件目录>     # 产出 .channekplugin
```

pack 按与**安装侧同一份**内容黑名单先剥干净（`.git*` / `.github/` / `.npmrc` /
`node_modules` / 疑似密钥），而安装侧对这些是**整包拒**——手工 zip 出来的包能上架、能下载、
指纹也对，最后卡在每个用户机器上，作者收不到任何信号（实测多数只因为夹带了一个 `.gitignore`）。

打包前自检：

- [ ] 包里有 `package-lock.json`（有 npm 依赖时——宿主靠它替用户装依赖）
- [ ] 清单 `default` / `program` 无本机路径；实现自带（`{{pluginDir}}/…`）
- [ ] 无密钥、无 dotfile、无软链、无超大文件（安检一律拒）
- [ ] 插件用法 skill 放 `<插件根>/skills/`（跟插件一起分发，装上即被用户的 AI 读到）

## 分发三层（心智模型）

| 层 | 存什么 |
|---|---|
| 源码层 | 插件开发真身（你的 repo） |
| 制品层 | 打好的 `.channekplugin` / `.channekcard` + 签名 |
| 索引层 | 商店目录、搜索、版本、兼容区间、撤销名单 |

索引层不存制品，只存元数据 + 下载地址 + 签名指纹——撤销名单秒级生效（app 启动拉一次即可
拒装已撤销版本）。

## 签名与两条到达路径

| 路径 | 签名要求 |
|---|---|
| **独立分发**（用户导入目录 / symlink 开发流 / 商店下载） | 本地目录装**不要求签名**（有签名但验不过标警告、验签失败拒载）；T2 另过安装前知情同意（按 版本+摘要+权限清单 批准，变了重新确认）。商店安装的 T1/T2 必须有有效签名 |
| **随卡包捎带**（`.channekcard` 的 `plugins/`） | **包内 T1/T2 插件必须携带有效 ed25519 签名，否则拒装**（离线侧载没有商店索引可比对，签名是唯一防篡改锚）；T0 纯数据免签 |

随卡打包时收谁：`requires.plugins`（含从步序反推的）∩ 本机已装 ∩ 非内置——内置插件人人都有
不带；没被卡要求的不带（既泄漏你装了什么，也让收卡人为用不上的代码过门）。

## 上架硬规则

- id 正则 `^[a-z0-9][a-z0-9-]*(\.[a-z0-9][a-z0-9-]*)+$` 且与目录名一致；`channek.` 前缀不得使用。
- 展示名不得含「Channek」字样或以其它方式冒充官方。
- 命令 id 必须 `<pluginId>.` 前缀。
- manifest 必须过 `validateManifest`（目录 CI 与本地 `plugin-cli validate` 同一执行体），
  error 级问题直接拒收。
- 上架物料走 manifest `marketplace` 段（icon / screenshots，收外链或包内路径——图放 CDN
  就不必打进包）。

## 协议演进纪律（对作者的含义）

manifest 与扩展点 decl 发布后**只增不改**（只能追加可选字段）；已发布能力的 inputs 改类型 /
改必填 / 删字段 = 破坏性变更，只能新开 id 并给老 id 弃用期。你依赖的宿主契约同样受此保护——
`@channek/sandbox-sdk` 的导出面是公开 API，不会在小版本里被抽走。
