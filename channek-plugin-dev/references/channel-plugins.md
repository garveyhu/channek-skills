# 频道插件：住在频道文件夹里的插件

**一句白话**：频道插件就是一个普通插件，只是它的文件夹放在**某个频道里面**，由那个频道的频道卡
`channel.json` 点名。它只在这个频道加载，跟着频道一起分享——别人拿到这个频道，插件就在里面。

manifest、信任级、扩展点、桥、校验规则和全局插件**完全一样**；不一样的只有四件事：
**放哪、怎么被发现、谁信任它、怎么分发**。本篇把这四件讲全。

## 1. 先判断：做成频道插件还是全局插件

| | 频道插件 | 全局插件 |
|---|---|---|
| 住哪 | 频道里，推荐 `plugins/<插件id>/` | 本机插件目录（`~/.channek/plugins/<插件id>/`） |
| 怎么被发现 | **只认频道卡 `plugins` 里写的路径**，不扫描 | app 扫插件目录 |
| 谁能用 | 只有声明它的这个频道 | 任何频道（按频道启用） |
| 频道卡怎么引用 | `"plugins": ["plugins/<插件id>"]` | `"requires": { "plugins": [{ "id": "<插件id>" }] }` |
| 信任 | 按**频道**信任（频道的真实路径 + 代码指纹） | 按插件信任，A 频道信任过，B 频道不再问 |
| 分享 | 是频道的文件，导出 `.channel` 时自然带走 | 单独发 `.ckplugin`；卡包可按 `requires` 捎带 |
| 典型 | 某个频道专属的功能区、进度分析器、运营面板 | 出图、配音、转写、发布平台 |

判据一句话：**只有这一个频道用得上 → 频道插件；两个以上频道都要用 → 全局插件。**
拿不准就先做成频道插件——「第二次用到才抽出来」，抽的办法见第 8 节。

## 2. 放哪、怎么声明

```
acme.talkfast/                     ← 频道根
├── channel.json                   ← "plugins": ["plugins/acme.talkfast-suite"]
├── plugins/
│   └── acme.talkfast-suite/       ← 目录名必须等于 manifest 的 id
│       ├── manifest.json
│       ├── package.json · package-lock.json · src/ · build.mjs   ← 源码，随你
│       └── dist/                  ← 构建产物：manifest 的 entries 指向这里
├── sop/ …
└── work/ …
```

频道卡里的声明：

```jsonc
{
  "schema": "channek.channel",
  "formatVersion": 2,
  "name": "口播快剪",
  "card": { "id": "acme.talkfast" },
  // 数组，可以写多个；每项是相对频道根的插件目录
  "plugins": ["plugins/acme.talkfast-suite"],
  // 卡的其它段照常引用它贡献的 id
  "presentation": {
    "sections": [{ "id": "channek.home" }, { "id": "acme.talkfast-suite.assets" }]
  }
}
```

硬规则（违反任何一条，这个插件都不会加载，频道右上角的「还差 N 件事」里会写原因）：

- **目录名 = manifest 的 `id`**（清单校验 V2：`plugin id must match directory name`）。
- **路径相对频道根、不含 `..`、不是绝对路径**；按真实路径解析后**必须仍在频道文件夹里**——
  频道里放一个指向外面的软链会被拒（「解析后逃出了频道目录」）。目录不存在也会被拒。
- **只认声明、不扫描**：文件夹放进 `plugins/` 但卡里没写，就等于没有。旧版的
  `<频道>/.channek/plugins/` 早已不再扫描。
- **别放进会被分享剥掉的地方**：`layout.contentDir`、没标 `recipe` 的 `layout.sections`、
  `bundle.omit` 列出的路径、点开头的目录（`.channek/`、`.claude/`）——放进去，你自己能用，
  收卡人拿到的频道里却没有它。
- **不要再写进 `requires.plugins`**：那是全局插件的 id 清单，写了会让 app 去本机插件库里找一个不存在的全局插件。

卡里引用频道插件贡献的东西，和引用全局插件一样写 id：

| 频道插件贡献了 | 卡里在哪引用 |
|---|---|
| `ui.suiteSection`（功能区，建议 `declaredOnly: true`） | `presentation.sections[].id`，要它当首页就写 `presentation.defaultSection` |
| `production.step` / `ui.contentStep`（步骤） | `pipeline.steps[].step` |
| `production.analyzer`（进度分析器） | `layout.progressAnalyzer` |
| `workspace.artifactKind`（工件种类） | `layout.artifacts` 的键 |
| 清单里的 `channelConfig`（频道参数段） | `config.sections` 里的插件段 `{ "id": "<段 id>", "plugin": "<频道插件 id>", "values": { … } }` |

## 3. 能做什么、不能做什么

- **三级信任都允许**（T0 / T1 / T2），能贡献的扩展点和全局插件一样。
- **只在声明它的频道里生效**：别的频道看不见、启用不了它；在本频道默认启用。
- **生命周期跟着频道窗口**：频道打开且已被信任时加载；这个频道的最后一个窗口关掉时停用
  （T2 在插件进程里 `deactivate`，超时强制回收）。
- **改不了自己，也改不了卡**：桥的 `channel.writeFile` 对频道卡和频道插件目录是只读的。
  插件的数据写到频道里别的地方，或用插件存储（`storage`，可按频道分份）。
- **T2 仍然是全 app 一份实例**：两个频道窗口同时开着时，「这次替哪个频道干活」照样从调用带来的
  `workspaceRoot` 取，别自己记一个「当前频道」（见 `trust-tiers.md` 的 T2 运行时要点）。

## 4. 信任门：别人第一次打开带频道插件的频道

频道可能来自网盘、git 或别人的卡包——**打开一个文件夹 ≠ 同意运行它带的代码**。所以：

1. **信任之前什么都不加载**：插件进程不激活、`plugin://` 资源不放行、界面不装配、skill 不推送。
   频道照常能打开、能看文件，只是这些插件还不在。
2. **在哪信任**（app 0.1.1 的界面）：
   - 频道标题栏右上角「还差 N 件事」→ 那条「频道自带插件 · 待信任」→「查看」；
   - 或 设置 › 本频道 ›「需要处理」→「频道自带插件待信任」→「信任并加载」；
   - 或 设置 › 插件 › 打开那个插件的详情页 →「信任并加载」。
   信任**按频道记**（频道文件夹的真实路径），一次信任这个频道里的全部频道插件；信任了 A 频道不等于信任了 B 频道。
   详情页的「撤销信任」= 这个频道以后不再加载它们。
3. **T2 还要逐个批准**：频道被信任之后，特权插件和全局 T2 一样，要在插件页按代码指纹单独批准一次。
4. **防篡改**：信任时记下代码指纹，之后代码一变就自动停用、等你重新确认。
5. **信任不认卡里写的 id，认路径和代码**：拷一份频道就能冒充 id，冒充不了路径和指纹——
   所以把频道挪到别的路径、或拷一份出来，都要重新信任。

写给收卡人的说明（README / STOREFRONT）里提一句「打开后在右上角信任一下频道自带插件」，能省掉大半「插件怎么没出来」的提问。

## 5. 开发模式：作者在自己的频道里开发

1. 建 `plugins/<插件id>/`，写好 manifest，先单独验插件：

   ```bash
   channek check plugins/acme.talkfast-suite    # 清单校验，和 app 装插件同一份判据
   ```

2. 在 `channel.json` 的 `plugins` 里加上这一行，再验频道：

   ```bash
   channek check .                              # 在频道根跑
   ```

   注意它**只核对插件目录在不在**，并用频道插件清单里的 `channelConfig` 校验卡里对应的插件段；
   **不会**替你校验插件清单本身——第 1 步那条不能省。
3. 在 app 里打开频道 →「信任并加载」→ 设置 › 插件 › 打开这个插件的详情页，打开 **「开发模式」** 开关
   （「代码变更后自动重新加载，无需逐次确认。仅对本频道生效」）。打开之后，这个频道的插件按**路径**认身份，
   改代码不再被当成篡改；打开那一下 T2 可能要重新批准一次。
4. 改代码 → 构建 → app 监视着卡里声明的插件目录，会自动重扫。**新代码什么时候真的生效**和全局插件一样：

   | 改了什么 | 怎么让它生效 |
   |---|---|
   | T0 的 manifest / 资源 | 自动重扫即可 |
   | T1 沙箱页（html / css / js） | 重载整个窗口——已经挂着的 iframe 不会自己重载 |
   | T2 的 `main` 代码 | 重启 app——宿主进程里的模块被 Node 缓存 |
   | T1 / T2 的 manifest（尤其权限） | 可能停在「待批准」，再批准一次 |

5. **只给自己的频道开开发模式**。从别处来的频道默认是关的，也应该一直关着。
6. **同时开着它的一份拷贝时**：两个频道带着同一份代码时共用一个实例；你在开发模式下一改代码，
   两份就不一样了，拷贝那边会被拒载（提示「另一个打开的频道里有代码不同的同名插件」），关掉你的频道后它才接上。
   这是正常的，不是坏了。

排错：

| 症状 | 先查 |
|---|---|
| 插件根本没出现 | 卡里 `plugins` 写了吗？路径对吗？目录名 = id 吗？右上角「还差 N 件事」里有没有「频道插件路径无效」 |
| 出现了但没加载 | 还没信任（右上角「待信任」）；T2 还没批准 |
| 提示「与本机已安装的插件同名」 | 你装过一个同 id 的全局插件（含软链进插件目录的开发版）——频道插件不许顶替它，删掉其中一份 |
| 提示「另一个打开的频道里有代码不同的同名插件」 | 另一个开着的频道带着这个插件的另一版，关掉那个频道 |
| 改了代码没变化 | 开发模式开了吗？按上表重载窗口 / 重启 app |
| 代码一改插件就停了 | 没开开发模式，被当成篡改停用——重新信任，或打开开发模式 |

## 6. 撞名规则（id 怎么起）

插件的隔离单位是 id：`plugin://<id>` 一插件一源，存储、设置、密钥注入都按 id 分。所以：

- 频道插件的 id **和内置或全局插件相同 → 拒载**，哪怕全局那份坏了也一样——不许频道里的代码冒名顶替一个你信任过的插件。
- 两个开着的频道带着同一个 id：**同版本、此刻代码指纹相同 → 共用一个实例**（拷贝出来的频道是常态），
  但每个频道仍要各自过信任门；**代码不同 → 后来的那个拒载**。
- 所以 id 用你自己的发布者前缀，并且别和你发布过的全局插件重名（`acme.talkfast-suite`，而不是 `acme.suite`）。

## 7. 分享频道时它怎么跟着走

**导出 `.channel`**（用 app 的导出功能，不手工 zip）：频道插件就是频道的做法文件，跟频道卡一起进包；
它不走「随卡捎带的全局插件」那条路。进包时按和插件包同一份内容黑名单剥掉：

- 点开头的文件与目录（`.git`、`.env`、`.DS_Store` …，`.gitkeep` 除外）；
- `node_modules/`、`__pycache__/`、`*.pyc`；
- 疑似密钥（`*.pem`、`*.key`、`id_rsa`、名字带 `env` / `secret` 的数据文件如 `secrets.json`）；
- 软链、超大文件；再加上 `layout` 的内容区和 `bundle.omit` 里写的路径。

导出**不读 `.gitignore`**，也**不替你构建**。由此推出三条：

1. **导出前先构建**，`dist/`（manifest 的 `entries` 指的那些文件）必须在。
2. **运行时不能依赖 `node_modules`**——它不会进包。T1 把依赖（含 `@channek/sandbox-sdk`）打进自己的 bundle；
   T2 本来就要求单文件 CJS，把依赖打进那一个文件。
3. **构建垃圾自己清**：sourcemap、分析文件这类东西黑名单不认识，留在插件目录里就会跟着进包。

导出器还会提示做法文件里写死的频道名或人设——插件源码里的也算，能改成从 `card.config` 读的就改。

**收卡人导入**：用卡开新频道是拷贝，频道插件落进新频道自己的文件夹（**不进全局插件库**）；
新频道第一次打开时过第 4 节的信任门，开发模式默认关。随卡捎带的全局插件才有签名那套要求，频道插件靠的是信任门。

**用 git 分享频道**：`dist/` 要入库（别人 clone 下来不必先装开发依赖再构建就能加载），`node_modules/` 不入：

```gitignore
node_modules/
# 频道插件的构建产物要跟着频道走
!plugins/*/dist/
```

## 8. 什么时候提升成全局插件，怎么搬

**信号**：第二个频道也想用它。别把插件目录再拷一份进第二个频道——两份代码会各改各的，同时开着时还会互相拒载。

当前版本的 app **没有一键提升命令**，照下面手工搬：

1. **把 `plugins/<插件id>/` 移出频道**，变成一个独立的插件目录（或独立仓库）。**id 不变**——
   存储、设置、密钥注入都按 id 分，换 id 等于丢掉已有数据、还要改所有引用。
2. **先改频道卡**：每个要用它的频道，删掉 `channel.json` 里 `plugins` 的那一行，改在
   `requires.plugins` 里写 `{ "id": "<插件id>" }`；`presentation`、`pipeline`、`config` 里对它的引用不用动（id 没变）。
3. **再装成全局插件**：开发期把目录软链进本机插件目录（见 SKILL.md 第 5 步）；或 `channek plugin pack` 打成 `.ckplugin` 再导入。
   顺序反了也不会坏：频道那份会以「与本机已安装的插件同名」被拒载，用的是全局那份，只是多一条提示。
4. **在每个频道里启用它**（新频道的第三方插件默认不启用；卡里写了 `requires.plugins`，
   设置 › 本频道会提示「频道卡要求的插件未启用」），并重新过全局插件的信任（T2 批准）。

之后它就按全局插件的规矩活：单独发版、单独分发，卡包按 `requires` 捎带。

## 9. 自检清单

- [ ] 确实只有这一个频道用（否则做全局插件）
- [ ] 目录 `plugins/<插件id>/`，目录名 = manifest `id`，id 带你自己的发布者前缀、不和任何全局插件重名
- [ ] `channel.json` 的 `plugins` 里写了相对路径；没写进 `requires.plugins`
- [ ] 插件目录不在内容区、没标 `recipe` 的区、`bundle.omit` 里，也不是指向频道外的软链
- [ ] `channek check plugins/<插件id>` 与 `channek check <频道根>` 都零错误
- [ ] `dist/` 已构建、入口文件都在；运行时不依赖 `node_modules`
- [ ] 开发模式只在自己的频道开
- [ ] 收卡人说明里写了「打开后信任频道自带插件」
